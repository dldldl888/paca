## 1. 问题、目标与范围

| 已复现的问题 | 修复后的可观察行为 |
|---|---|
| 桥接重启后同一 Paca 会话忘记随机标记，原历史仍在 | 重启和闲置回收后可继续原生 Hermes 会话，正确复述标记；历史不重复 |
| 同项目 B 能读取 A 的任务并收到更新 | 未获对象授权的 B 在详情、列表、搜索、统计、相关内容、写入和实时通道均不能获得 A 的任务数据 |
| B 的原生 session_search 能读取共享 Hermes 状态中的 A 历史 | B 的进程、历史工具、记忆与文件工具无法访问 A 的状态；同任务的两人私聊也独立 |

沿用 Paca `59e871b`、Hermes `2179a279` 与两个合成测试账号。正常模型会话已有 12/13 项通过，本轮保留这些能力并修复剩余上下文恢复项。此数字不包括全部权限测试。

不在本轮扩展：前端重设计、领导任务草稿/确认发布、多人共享私聊、跨会话长期记忆共享、生产部署及并发扩容。原模型 401 被标成 finished 的问题单独保留；本轮新引入的恢复/授权失败必须走 failed，不能沿用这一缺陷。

## 2. 确定的权限规则

默认拒绝，先验证有效身份及当前项目资格，再验证动作权限与对象关系。角色名称、前端筛选、可编辑 reporter_id、客户端提交的 user_id 都不是对象授权依据。

| 动作 | 普通员工 | 获授权的项目经理 / 管理员 |
|---|---|---|
| 查看任务 | 当前负责人，或可靠创建者 | 在管理范围内可查看全部任务 |
| 修改任务 | 当前负责人可更新执行状态、提交进展；需既有写权限 | 在管理范围内按动作权限修改 |
| 创建正式任务、改派、改要求、改期限、删除 | 无管理权限时拒绝 | 需任务管理权限 |
| 读取自己的私聊与通知 | 沿用现有归属检查 | 同样仅本人；任务管理权不赋予他人私聊阅读权 |
| 同一任务中的两人私人提问 | 各自独立历史、记忆、运行目录 | 不合并私人上下文 |

- 在既有权限注册表增加 `tasks.read_all` 与 `tasks.manage`，仍要求对应 `tasks.read` / `tasks.write`。`tasks.*` 和合法全局管理通配权限涵盖新增权限；普通员工的 read/write 不等于 read_all/manage。
- 全局管理特权与项目级特权分别解析，项目经理不能越过自己的项目。管理员不因此读取私人会话。
- 添加不可由客户端写入的 `creator_user_id`，由认证身份生成。旧任务没有可信创建证据时保持 NULL，不把 reporter_id 或最后操作者回填成创建者。旧任务仍可由负责人和授权管理者访问。
- 本轮不添加共享 ACL 表或分享界面。提及、订阅、评论、父子关系与任务链接不自动授予访问权。
- 读不到的对象返回现有 not-found 语义，禁止修改可读对象的受限字段返回 forbidden；拒绝必须发生在事务、附件签名、事件或通知等副作用之前。
- 查询权限作为服务端谓词，与用户筛选取交集，在分页、计数、聚合之前应用。不能依赖前端过滤或逐页删除无权结果。
- 内部自动化调用必须显式标识受限的服务身份及对象范围；缺少用户上下文不能自动变成管理员。追踪调用方后复用共同鉴权入口，不在每个 handler 复制一套规则。

## 3. 推荐的最小方案

### 3.1 Paca 任务与实时通道

复用任务 service/repository 和既有 authorizer。将对象检查接入详情、按编号查询、写入、评论/活动/标注、附件、父子/依赖关系、任务关联会话、列表和 sprint/view/首页聚合等真实入口。不得只修 `GET /tasks/:id`。

任务内容及任务关联的项目共享 Agent 事件不再直接发进项目 tasks 房间。沿用用户房间，由服务端共同权限逻辑决定当前收件人。实时服务不得另写一套角色判定；权限解析失败时丢弃敏感载荷。仅有通用项目权限不足以成为收件人。

改派、降权、移除成员和停用账号必须使后续 HTTP、排队调度及实时投递使用新权限。对已连接 socket 也生效，覆盖已入队但尚未发送的事件。可保留此前合法产生的个人通知历史；不得向已失权者新增含受限任务内容的通知。已经合法看到的数据无法收回。

### 3.2 Hermes 隔离边界

私人运行标识由 Paca 持久会话记录解析，绑定实例、Agent、项目、所有者和 conversation ID。每个私人会话使用独立进程及独立的 HERMES_HOME、工作目录和临时目录；同人跨项目和同任务跨员工都不共享这些可变状态。

桥接接收的身份来自已认证的后端派发，不能让浏览器传入 owner 或本地路径。私人会话不得受 `session_scope=task/agent` 合并；明确的项目共享运行采用另一命名空间，不允许没有 owner 的私人运行退化成共享运行。专用企业 Hermes 实例只接收已验证的私人交互；已有任务自动运行不应借此得到用户委托权限。

复用本机已验证的 macOS 文件沙箱，按每个会话收窄实际读写范围及子进程范围。0700 文件夹在同一 OS 用户下不足以构成隔离。允许必要的 Hermes 程序/运行时、可信配置和本会话目录，禁止其他会话、共享历史库、个人 Hermes 目录及个人文件；拒绝路径穿越和符号链接逃逸。不要把整个隔离根目录放入白名单。

由可信启动端提供必要模型配置，凭据不进入源码、映射、日志或可分享材料；不向 Hermes 传递 Paca 管理员 cookie 或 bridge token。沿用本次专用实例的受限工具配置，不新增能用 Agent 全局身份读取业务数据的工具。保留原生 history/memory 工具在本会话内的有效功能，并用实际工具调用检验边界。

### 3.3 原生上下文恢复

Hermes 已声明 `load_session=True` 并实现 `load_session`。优先复用它。直接拼接 Paca 文本历史会损失工具消息语义；保持进程永不退出不能解决桥接重启，均不作为本轮方案。

桥接在可信持久目录保存最小映射：运行身份、原生 session ID、固定 cwd 和版本。只保存元数据，不复制对话。原子写入并限制权限；提交成功后才发出该会话的第一轮 prompt。不得把映射放进工作目录供模型修改。

重新启动、子进程退出或闲置回收后，根据同一身份读取映射，执行 initialize → 检查能力 → session/load → prompt。回收只释放进程，不删除映射或 Hermes 持久状态。同一会话仍串行，沿用既有 busy、queue 和 stop 机制。

`session/load` 在响应返回前会发出历史 `session/update`。加载期间的重播不得作为本轮新事件写回 Paca、重复显示或触发工具执行；load 完成后只接收匹配当前原生 session 的新输出。

映射损坏、身份/cwd 不符、原生会话不存在、load 返回 null/无效结构或能力不支持时，关闭未绑定进程并报告可重试的恢复失败；不发送本轮 prompt、不静默 new session。后端派发提供可信的既有轮次信息，区分真正首次会话与丢失映射的旧会话。断电发生在原生创建和映射提交之间时不得覆盖可识别的旧状态；孤立且从未发送 prompt 的原生会话可保留供维护清理。

成员撤权或关联任务失权后，不再装载旧任务上下文或继续排队/活动生成。原主人此前合法保存的私人历史可继续按现有归属规则浏览；上下文恢复不产生新的业务授权。

### 3.4 旧验证数据与回退

旧测试使用混合 Hermes home，不能整体复制到每个新会话。仅在 Paca owner、原生 session ID 和历史归属都能可靠核实时做单会话迁移；不能核实的旧记录保留历史，并明确提示无法恢复，使用新的独立会话开展验收。不得声称所有升级前会话均自动恢复。

修改放在独立 `codex/context-recovery-isolation` 分支/工作区。本地接入更新前保存专用验证配置与数据库备份，实施增量迁移，验证后再更新专用 bridge/API/realtime。若回退代码会重新开放旧权限漏洞，应暂停测试实例的相关访问，不能在真实数据场景下直接回退到不安全行为。本轮只使用合成数据。

## 5. 验收与质量门

- A/B 双向测试；经理可管理授权项目，非该项目经理不可越权。API 拒绝、列表零泄露、聚合不含受限数据、数据库无越权副作用与实时零敏感载荷分别断言。
- 同一任务关联 A/B 两个私聊，各写入随机标记；B 的无工具问答、真实 `session_search`、直接按 A session ID 加载、记忆/文件读取均不能获得 A 标记。验证本人当前会话工具仍可用。
- 真实模型在停止、浏览器/Socket.IO 重连、bridge 重启、ACP 子进程退出和闲置回收后分别正确记住标记；已有消息 ID/顺序不变，无重播重复与自动再执行副作用。忙碌、显式排队和生成中停止仍通过。
- 故障注入：缺失/损坏映射、错误 owner、错误项目、路径穿越/符号链接、缺失原生会话、load 不支持或超时。均保持历史、阻止无效 prompt、不给另一个人恢复上下文。
- 覆盖撤权时 socket 保持连接、任务已入队、回复正在流式生成、重新续聊等情况。无权用户不得从旧缓存、旧房间或延迟事件继续取得新数据。
- 复用现有 Go 单元/e2e、Bun/TypeScript 与 Python 联调能力，不引入新测试框架。必要的测试入口随实际语言绑定，不为迁就模板把 Go 改写成 Python。
- 每条 story 执行其真实测试、相关 Go build/test 或 TypeScript check；最终执行受影响模块回归、已保留的 8/8 私聊隔离、13 项真实模型行为与新增权限/工具/恢复检查。真实模型与真实沙箱检查不能只用 mock 替代。
- 在浏览器验证 A/B 登录、自己的任务与通知、他人的任务被拒绝、私聊续接和状态反馈；鼠标发送受 Devtools 遮挡的既有问题如未修，报告必须保留，不能宣称鼠标发送通过。
- 更新本轮独立验收报告，保留旧失败证据；注明命令、源码版本、通过/失败/未测与证据位置。敏感 runtime 目录不得提交。
